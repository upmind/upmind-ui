# ui-gaps.md — design-system gaps recorded from portal-nuxt

Two registers. The first is read by `apps/portal-nuxt/tests/ui-gaps-register-completeness.test.ts`: every portal file that imports a design-system family's raw `parts/` instead of its composed form must have a row naming the file and at least one part. The second lists composed-component gaps the portal worked around; they are fixed in `design-system`, never in the portal.

## Parts-over-composed reaches

| File                   | Composed form    | Parts reached                                                                                                                                                                                                                                                                        | Why the composed form did not fit                                                                                                                                                                          | Status                                                                  |
| ---------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `PortalSettings.vue`   | `Select`         | `SelectRoot`, `SelectTrigger`, `SelectValue`, `SelectContent`, `SelectItem`                                                                                                                                                                                                          | The composed `Select` takes a flat `items` prop; the settings dialog renders theme options with a swatch inside each item, which needs the item slot the parts expose                                      | open — composed `Select` needs an item-render slot                      |
| `PortalSettings.vue`   | `SettingsDialog` | `SettingsDialogRoot`, `SettingsDialogTrigger`, `SettingsDialogContent`, `SettingsDialogSidebar`, `SettingsDialogNav`, `SettingsDialogItem`, `SettingsDialogMain`, `SettingsDialogSearch`, `SettingsDialogPanel`, `SettingsDialogSection`, `SettingsDialogGroup`, `SettingsDialogRow` | `SettingsDialog` ships parts only; there is no data-first composed form taking sections and rows as props                                                                                                  | open — a composed `SettingsDialog` with `sections` data                 |
| `Command.vue`          | `Command`        | `CommandDialog`, `CommandInput`, `CommandList`, `CommandEmpty`, `CommandGroup`, `CommandItem`, `CommandShortcut`                                                                                                                                                                     | The composed `Command` has no dialog (⌘K) mode and no `groups` data prop; the palette needs both                                                                                                           | open — composed `Command` with `dialog` + `groups`                      |
| `List.vue`             | `List`           | `ListRoot`, `ListItem`, `ListItemTitle`, `ListItemDescription`                                                                                                                                                                                                                       | The composed `List` renders title/description only; the portal row needs leading media, trailing badge, cells, time, action button and an overflow menu per item                                           | open — composed `List` item needs media/trailing/actions slots or props |
| `List.vue`             | `Card`           | `CardRoot`, `CardHeader`, `CardTitle`, `CardDescription`, `CardAction`, `CardFooter`                                                                                                                                                                                                 | The grid variant renders each row as a card with an action in the header and a footer; the composed `Card` exposes no header action or footer prop                                                         | open — composed `Card` `action` + `footer` props                        |
| `Menu.vue`             | `SidebarNav`     | `SidebarNavRoot`, `SidebarNavLink`                                                                                                                                                                                                                                                   | The composed `SidebarNav` owns active-state matching by exact path; the portal's rule is "deepest destination wins" over query-carrying links, so the module drives `active` per link                      | open — composed `SidebarNav` `activeMatch` prop                         |
| `PortalSidebarNav.vue` | `SidebarNav`     | `SidebarNavRoot`, `SidebarNavLink`                                                                                                                                                                                                                                                   | The composed `SidebarNav` renders one flat list from one `items` array — no nested levels, no back row, no focus handover — so the sidebar's `nested` variant composes the parts and owns the level itself | open — composed `SidebarNav` nested `items` with drill-down             |
| `Notifications.vue`    | `List`           | `ListRoot`, `ListItem`, `ListItemTitle`, `ListItemDescription`                                                                                                                                                                                                                       | Same as `List.vue`: unread badge, time and per-item dismiss action per row                                                                                                                                 | open — see `List` row                                                   |

## Composed-component gaps worked around in the portal

| Component            | Gap                                                                                                                                                                                                          | Portal workaround                                                                                                                                                                                                                       | Status                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| `Tabs`               | Renders one panel per tab unconditionally; a rail over external content leaves an empty panel under itself                                                                                                   | `ui.content: "empty:hidden"` on the tabs module (`portal-mock-composable-facades.md` §6)                                                                                                                                                | open — a panel-less rail prop                                  |
| `Stat` / `StatGroup` | No link capability; dashboard tiles cannot navigate to their lists (legacy tiles do)                                                                                                                         | metric module wraps the tile in `Link` when `to` is set                                                                                                                                                                                 | open — `to` on `Stat`                                          |
| `Pagination`         | No click emits on the arrows for a controlled pager                                                                                                                                                          | pagination module owns the arrow buttons and emits its own action values                                                                                                                                                                | open — `update:page` emit                                      |
| `DateRangePicker`    | Ships as a `parts/` export only                                                                                                                                                                              | list-controls date-range filter renders two `DatePicker`s                                                                                                                                                                               | open — composed `DateRangePicker`                              |
| `ActionPane`         | Removed from the library on this branch; the `utility` primitive has no column-or-drawer component                                                                                                           | `shell/PortalActionPane.vue` composes an `<aside>` at lg+ and the composed `Sheet` below it, with the open state bound by `PortalFrame`                                                                                                 | open — an `ActionPane` (or its equivalent) back in the library |
| `BottomNav`          | Removed from the library on this branch; the `bottom` primitive has no destination strip                                                                                                                     | `modules/bottom-nav/` renders its own `<nav>`/`<ul>` of links wearing the removed bar's classes (`modules/bottom-nav/variants.ts`)                                                                                                      | open — a `BottomNav` back in the library                       |
| `Shell`              | No `level` on `ShellHeader` and no `#bottom` region: three stacked bars share row 1 and overlap, and a bottom bar has nowhere to mount                                                                       | `PortalFrame` declares its own five-row grid (`shell/variants.ts` `CHROME_PANEL_CLASS`), places each bar with `chromeLevelClass`, binds each sub-bar's own running `--shell-sticky-offset`, and renders the bottom strip viewport-fixed | open — `ShellHeader` `level` + a `Shell` bottom region         |
| `Page`               | No `PageFooter` part                                                                                                                                                                                         | `PortalPageHost` renders a `data-slot="page-footer"` band (`content/variants.ts` `PAGE_FOOTER_CLASS`)                                                                                                                                   | open — a `PageFooter` part                                     |
| `List`               | `ListRoot` lost its `layout` variant, so `masonry` has no multi-column flow                                                                                                                                  | `modules/list/variants.ts` `masonryClass` supplies the column flow and the module passes `divided: false` for it                                                                                                                        | open — `ListRoot` `layout: masonry`                            |
| `Form` (`src/form`)  | `FormEngineData` carries countries only; a money field has no currency channel                                                                                                                               | `mock/forms/engine-data.ts` exports the currency list for a schema's own `enum` instead                                                                                                                                                 | open — currencies on `FormEngineData`                          |
| `DropdownMenu`       | `MenuItem` has `disabled` but no reason/title channel, so a disabled entry cannot say WHY it is disabled (the `Button` module's `disabledReason` reaches a `title` on a real button; a menu item's does not) | list/button modules pass `disabled: action.disabledReason !== undefined` and the reason itself never reaches the user                                                                                                                   | open — `MenuItem.disabledReason` (or `title`)                  |
| `Sanitized`          | DOMPurify strips `<iframe>`, so provisioning frames cannot pass through it                                                                                                                                   | `prose/frames` renders real sandboxed iframes                                                                                                                                                                                           | open — an allow-list for sandboxed iframes                     |
